# Create a profile manifest offline

Open [`scripts/thorium-profile-editor.html`](https://edrlab.github.io/thorium-reader/scripts/thorium-profile-editor.html) in your browser. You can copy this single HTML file anywhere and use it offline. It does not upload data or require installation.

1. Enter a unique profile identifier URI, such as `thorium-manifest://org.example.my-profile`. Keep the identifier when updating the same profile.
2. Enter the title and description. Use **Translations** to enter separate values by language, such as `en` and `fr`.
3. Check the creation timestamp and optionally enter a modification timestamp. ISO 8601 timestamps are recommended.
4. Set the eight colors for both light and dark themes. Use the color pickers for hex colors or type CSS colors directly. The previews illustrate the palette; they do not reproduce the complete Thorium interface.
5. Add images and links using the presets described below. These sections are optional.
6. Add publications and their book files and covers, if needed.
7. Optionally select your profile folder in **Folder check** to see which referenced files are present or missing.
8. Select **Download manifest.json** or **Export manifest.json**. Save the downloaded file under that exact name in your profile folder, then [pack and verify it with the CLI](customization-profile-cli.md).

**Import manifest.json** opens an existing manifest. Images, links, and publications appear as collapsible entries in their original order. Additional fields are preserved. Importing the manifest does not import its resource files: keep those files alongside the manifest in the profile folder with the same relative paths.

## Images and links

Choose a preset, then select **Add image** or **Add link**. Open an entry to edit its path or URL, relation, media type, optional language, and optional plain or multilingual title. Use **Duplicate**, **Up**, **Down**, and **Remove** to manage entries. Changes preserve imported custom fields, including nested properties.

| Preset | Purpose |
| --- | --- |
| Logo | `images` entry with `rel: "logo"`; starts with `image/svg+xml`. Change the media type if your logo uses another format. |
| Welcome image | `images` entry with `rel: "welcome-screen"`; starts with `image/png`. |
| Additional image / asset | Other resources, including files referenced only by HTML or CSS that must be included when packing. |
| Welcome page | Local HTML link with `rel: "welcome-screen"` and `type: "text/html"`. Add separate entries by language. |
| Navigation page | Local HTML link with `rel: "screen"` and `type: "text/html"`. Set its navigation title and language. Follow the [profile screen requirements](customization-profile-screens.md). |
| Catalog | An absolute HTTP or HTTPS OPDS catalog URL with `rel: "catalog"`. |
| Self link | A link with `rel: "self"`, identifying the profile's location. |
| Additional link | Another link with an optional custom relation. |

Paths use forward slashes, for example `images/logo.svg` or `screen/help-en.html`. Logos, welcome images, and HTML pages must use paths relative to the profile folder. Absolute filesystem paths, paths escaping the folder, and references to `manifest.json` are rejected. The editor does not read or preview resource files and does not fetch URLs.

For catalogs, enable **Configure catalog authentication** to set `properties.authenticate`. The media type must be `application/opds-authentication+json`; leave its URL empty to let Thorium discover authentication. Turning it off removes only `authenticate`, preserving other properties. Catalog order matters: Thorium uses the first catalog for authentication when activating the profile.

The JSON preview updates as you edit. Export reports missing metadata, invalid identifiers, duplicate or malformed language tags, invalid CSS colors, and resource field errors. Invalid entries open automatically and display their errors. The CLI checks that referenced local resources exist when packing. Existing signatures and content hashes are removed from the exported manifest and regenerated by the CLI.

## Publications

Select **Add publication**, then enter its book title and book file path or URL. The title supports translations. The guided form also edits the identifier, author, language, publisher, publication and modification dates, and description. Enter multiple book languages separated by commas, for example `en, fr-CA`.

New book links start as open-access EPUB acquisition links. Change their media type for PDF or other formats. Add additional links or covers as needed; both local paths and remote URLs are supported. Use the publication's **Duplicate**, **Up**, **Down**, and **Remove** controls to manage books independently of their links and covers.

Choose **Advanced JSON** to edit the complete OPDS publication object. This includes multiple contributors, collections, acquisition properties, and other metadata. Complex values that the guided form cannot edit remain intact; for example, an author array stays available in Advanced JSON while the guided author field is disabled. Simple contributor objects retain their extra properties when their displayed name changes.

The editors carry current edits across format switches. Invalid JSON blocks export, duplication, and switching to the guided form until corrected. Structures unsupported by the guided form, such as arrays of link relations, remain in Advanced JSON. Imported HTML descriptions are edited as text and never rendered.

## Folder check

Select the profile folder itself, with the same layout you will pass to the CLI. The browser supplies relative filenames; the editor does not read their contents, upload them, or change them. A checklist covers top-level images and links and each publication's images and links, matching the references collected by the packer. Duplicate normalized paths appear once with all their sources.

**Found** means the selected folder contained that exact relative filename. **Missing** means it was absent; a case mismatch is also shown, because filename case can matter on other operating systems. Remote URLs and fragment references are counted without fetching them. Folder checks do not inspect HTML or CSS, so declare any files used only by those documents explicitly in the manifest.

Results update when you edit the manifest. Reselect the folder after changing files on disk; folder selection is a snapshot. **Clear folder**, importing a manifest, and **New manifest** clear the selection. Folder checks are optional and missing files do not block downloading the manifest. The CLI performs the final filesystem and packaging checks, including checking that files are regular files and do not resolve outside the profile folder.

Changes remain in memory until you download the manifest. Download before closing the page. **New manifest** starts over with empty metadata, the current creation timestamp, and starter palettes.

For development instructions, see the [editor README](../projects/customization-profile-editor/README.md).
