## Scope and interpretation

The subsequent live BAnQ catalog audit confirms two catalog card names and adds **N02 (cover control role)** and **N03 (silent empty results)**. Reader identification is recorded; its broader native checks remain pending after earlier review timeouts. See the native sections below.

Baseline: [WCAG 2.2 Level A and AA](https://www.w3.org/TR/WCAG22/), interpreted for desktop software using [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/). WCAG conformance applies to complete interfaces and processes; a component check does not establish application conformance. Automated passes do not establish conformance either.

The original audit proceeded in two phases: static component/stylesheet review, followed by the running Electron application started with `npm run start:dev:quick`. That baseline included no source fixes. The continuation builds separate audit-only Library and Reader component fixtures, inheriting each renderer's loaders and runtime scope checker. Batch 1 now includes application changes on `codex/a11y-batch-1-names-labels`, based on audit commit `1fcc4fa782cf0b24441128903f40b48fd476bba5`. No direct imports between application runtime islands were introduced.

The component matrix covers Thorium-owned React components in shared renderer, Library and Reader code. PDF webview, EPUB publication content, Divina and audiobook surfaces require additional format-specific runtime evidence. Third-party publication accessibility is distinct from the accessibility of Thorium's controls. Source inventories describe potential UI, including conditional branches; they are not proof that every branch was rendered.

Statuses: **S** = source-confirmed defect; **D** = dynamically reproduced; **R** = risk requiring further evidence; **U** = untested; **cleared** = suspected issue disproved for the tested case. Severity is impact/priority, not a WCAG conformance level. Best-practice findings are distinguished from success-criterion failures.
